## Features

- **PR tools for the agent** — Coding sessions give the agent four tools for the pull requests in the chat header. `pr_status` returns a PR's state, checks, reviews, open conversations and merge state from what the header already fetched, so finding out whether CI passed no longer takes `gh` calls; it can also read another session's PR. `pr_bind` pins another PR to the session (from another branch, worktree or fork) and `pr_unbind` removes it. `pr_set_auto_merge` turns GitHub auto-merge on or off; the agent is told to use it only when you ask. The PR card has the same switch. It uses a merge method the repository allows, and when GitHub won't take auto-merge, the switch is greyed out and says why: the repository's **Allow auto-merge** setting is off, the PR is a draft, or nothing is left to wait for (GitHub only queues a merge while required checks or reviews are pending). A PR the agent opens with `gh pr create` is pinned automatically. Sessions outside Coding mode don't get these tools. Fixes [#1114](https://github.com/craft-ai-agents/craft-agents-oss/issues/1114).

- **Several PRs in one session** — The PR chip in the chat header now follows the branch's PR plus every PR pinned to the session. With more than one, the card starts with a tab per PR showing its number and status. Tabs that don't fit go into a "+N" menu, and ← / → step through them. The chip shows "+N" with the most urgent status among the other PRs (conflicts, then review comments, then failing checks), so a problem on another PR shows without opening the card. A pinned PR is marked Pinned and has an Unpin button. Resolve, Fix and Fix CI work on it in a separate checkout (the PR branch's existing worktree, a new worktree or a clone), so the session's folder keeps its branch. A copy button in the card's header copies the PR's link.

- **Auto-fix review comments** — The PR card's Fix button gets an **Auto** switch. While it's on, the session checks for new review comments every 5 minutes and starts a turn to address them. This also works while the window is hidden, another session is open or the screen is locked, and resumes after the app restarts; it doesn't run while the computer sleeps. Only comments from the repository's owner, members and collaborators count, never your own replies. The agent is told not to run commands or open links that a comment contains. Auto-fix works on the session's own branch PR, and waits while the PR has merge conflicts or the session is busy or in Explore mode.

## Improvements

- **Worktree picker finds nested repositories** — **Create new worktree** on the Coding chip now finds repositories up to four folders deep, in the workspace's default folder and in the folders that hold your recent repositories. It used to look only one level into the default folder. The scan stops at each repository, skips `node_modules`, `Library`, hidden folders and workspace data, and takes at most 2 seconds. The list's group is now called "On this computer". A default folder written with `~` (for example `~/Code`) is now scanned too.

- **Switching Coding mode is instant** — Clicking the Coding chip in a session that already started opens the new session right away. The summary of the conversation it carries over is now written in the background; it used to freeze the click for 5–8 seconds. A first message sent before the summary is ready waits for it, at most 30 seconds.

## Bug Fixes

- **Claude sessions apply Coding mode and your AI settings** — Claude sessions ignored four things that other providers applied. Coding mode (new in 0.15.4) kept the full system prompt and every session tool. Turning off **Settings → AI → Performance → Extended Context (1M)** still used the 1M window, and **Compact context at** (new in 0.15.2) had no effect. Images over 3.75 MB that the agent tried to read were refused instead of resized. All four now work in Claude sessions. A Claude Coding session started before this update gets the Coding tools, but keeps the system prompt it started with; start a new session for the shorter one.
