## Features

- **Coding mode** — A per-session mode that turns a session into a lean coding agent. It sends a much shorter system prompt (about 2.4K characters instead of 17K) and only the session tools coding work needs, so every turn costs fewer tokens and the model stays focused on your code. Your preferences, project context and the repository's CLAUDE.md/AGENTS.md still apply. Turn it on with the **Coding** chip next to the folder chip before the first message, start every new session in it with **Settings → Workspace → Start new sessions in Coding mode**, or pass `--coding` to `craft-cli run`. The mode is fixed once a conversation starts; clicking the chip in a started session continues in a new session with the mode switched, seeded with a summary of the conversation so far. Coding sessions show a `</>` glyph in the session list.

- **New worktree or existing folder** — Turning on Coding mode asks where the session should work. **Use existing folder** opens the folder picker. **Create new worktree** lists the repositories of your recent folders, those in the workspace's default folder, and your GitHub repositories (via the GitHub CLI), then creates a new branch (by default `craft/<session id>`) from the latest default branch in its own folder and makes it the session's working directory. A GitHub repository that isn't on your computer yet is cloned first. A bare-repository layout with many worktrees shows up as one entry.

- **Pull request status in the chat header** — In a Coding session whose folder is a git repository with an open pull request, the header shows the PR next to the folder name: its number, state (open, draft, merged in purple, closed) and one status mark — merge conflicts, open review conversations, failing checks, checks running, or a tick (orange while you have uncommitted changes or unpushed commits, green when all is good). Hover it, or click to keep it open, for the last commit, checks, reviewers, open conversations and merge state. One button sends a ready-made prompt to the agent: **Resolve** merge conflicts, **Fix** review comments or **Fix CI**; the agent works locally and doesn't push or reply on GitHub unless you ask. The status refreshes right after each agent turn and when you commit, switch branches or push, otherwise every 15 seconds to 2 minutes, and pauses while the window is hidden. It uses a connected GitHub source or your GitHub CLI login; no AI model is involved.

## Improvements

- **Claude Agent SDK 0.3.302** — Updated from 0.3.296 (Claude Code 2.1.302 parity), with the changes in between checked against Craft Agents: refused structured output, the new default permission mode for queries that don't set one, fork subagents and validated tool-input rewrites all behave as before.

- **Tidier chat header in Coding mode** — Coding sessions show one label chip plus "+N" in the header so the PR status has room, and the session title, not the labels, gives way on narrow panels.

## Bug Fixes

- **No more "on branch HEAD"** — A working folder on a detached HEAD no longer shows "on branch HEAD" next to the folder, and looking up the branch no longer blocks the app while git runs.
